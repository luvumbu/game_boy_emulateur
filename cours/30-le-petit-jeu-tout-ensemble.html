30. Le petit jeu : tout ensemble

Variables, conditions, boucles, tableaux, fonctions, struct : un vrai jeu, et rien d’autre.

1. Ce qu’il faut comprendre

Des objets tombent du ciel ; le panier (|#|) les attrape. Chaque objet attrapé rapporte un point ; chaque objet manqué coûte une vie. Toutes les notions du cours y sont, à leur place :

Variables : score, vies, la position du panier. Conditions : attrapé ou manqué ? partie finie ? Boucles : la boucle du jeu, et un for sur les objets. Tableau de struct : les trois Chute. Fonctions : lancer, attrape, dessinerPanier, dessinerScore. Méthode : tomber(). VBlank : le décor posé écran éteint, et chaque image n’écrit que ce qui a changé.

Un objet n’est jamais créé ni détruit : il est recyclé. Quand il arrive en bas, lancer(i) le renvoie en haut, à une colonne tirée au hasard. C’est la technique de presque tous les jeux Game Boy : un nombre fixe de places, qu’on réutilise.

attrape(i) est une fonction qui répond : l’objet est-il sur la ligne du panier, et entre ses deux bords ? Sa condition se lit comme la règle du jeu.

Le panier se redessine seulement s’il a bougé, le score seulement quand il change, et les objets un tour sur huit : c’est ce qui permet au panier de rester vif pendant que la pluie tombe.

Quand vies tombe à 0, on sort de la boucle du jeu par break, et le programme continue : « PERDU! ». Le while (true) de la fin garde l’écran affiché.

À toi : accélère la chute quand le score augmente (indice : remplace le 8 de attente == 8 par une variable qui diminue).

2. Le programme, morceau par morceau

Le programme entier de la leçon, découpé comme l’œil le lit. Il fait 2150 octets de cartouche.

1. une constante — COMBIEN

const uint8_t COMBIEN = 3;

2. une constante — SOL

const uint8_t SOL = 16;

3. un enregistrement — Chute

struct Chute {
  uint8_t x;
  uint8_t y;

  void tomber() { y++; }
};

4. un tableau — pluie

Chute pluie[COMBIEN];

5. une variable — panier

uint8_t panier = 8;

6. une variable — ancienPanier

uint8_t ancienPanier = 8;

7. une variable — score

uint8_t score = 0;

8. une variable — vies

uint8_t vies = 3;

9. une fonction — lancer()

void lancer(uint8_t i) {
  pluie[i].x = 1 + hasard() % 18;
  pluie[i].y = 2;
}

10. une fonction — attrape()

uint8_t attrape(uint8_t i) {
  return pluie[i].y == SOL && pluie[i].x >= panier && pluie[i].x <= panier + 2;
}

11. une fonction — dessinerPanier()

void dessinerPanier() {
  texte(ancienPanier, SOL, "   ");
  texte(panier, SOL, "|#|");
  ancienPanier = panier;
}

12. une fonction — dessinerScore()

void dessinerScore() {
  nombre(7, 0, score);
  nombre(18, 0, vies, 1);
}

13. le point d’entrée : c’est ici que la console arrive

int main() {
  ecran(0);
  texte(0, 0, "SCORE:");
  texte(12, 0, "VIES:");
  texte(0, 17, "GAUCHE    DROITE");
  for (uint8_t i = 0; i < COMBIEN; i++) {
    lancer(i);
    pluie[i].y = 2 + i * 4;
  }
  dessinerPanier();
  dessinerScore();
  ecran(1);

  uint8_t attente = 0;

  while (true) {
    image();

    /* le joueur : a chaque image */
    if (bouton(DROITE) && panier < 17) panier++;
    if (bouton(GAUCHE) && panier > 0) panier--;
    if (panier != ancienPanier) dessinerPanier();

    /* la pluie : un tour sur huit */
    attente++;
    if (attente < 8) continue;
    attente = 0;

    for (uint8_t i = 0; i < COMBIEN; i++) {
      texte(pluie[i].x, pluie[i].y, " ");
      pluie[i].tomber();

      if (attrape(i)) {
        score++;
        lancer(i);
        dessinerScore();
      } else if (pluie[i].y >= SOL) {
        vies--;
        lancer(i);
        dessinerScore();
      }

      texte(pluie[i].x, pluie[i].y, "O");
    }

    if (vies == 0) break;
  }

  texte(6, 8, "PERDU!");
  texte(4, 10, "SCORE:");
  nombre(11, 10, score);

  while (true) {
    image();
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée.

4. Ce que les touches changent

Chaque bouton que le programme lit a été enfoncé douze images, puis relâché. Voici l’écran juste après.

5. Ce qu’on doit voir

Trois O qui tombent, un panier |#| que GAUCHE et DROITE déplacent ; sans rien faire, « PERDU! » s’affiche au bout de quelques secondes.

6. Ce que la console répond

Ces contrôles sont ceux que verification/verifier-cours.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • le panier est à l’écran
  • des objets tombent
  • GAUCHE déplace le panier (8 puis 7)
  • chaque objet manqué coûte une vie : on tombe à 0 (après 160 images)
  • la boucle du jeu se termine par break : PERDU!
