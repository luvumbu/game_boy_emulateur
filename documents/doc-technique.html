Les bases — si tu n’as jamais programmé

Ces bases sont les mêmes que celles du cours complet. Si tu les as déjà lues, passe directement à la partie A.

0. Avant tout : ce document est fait pour toi

Tu n’as jamais programmé ? C’est exactement pour toi. Ce document ne suppose rien : chaque mot nouveau est expliqué la première fois qu’il apparaît, et il est aussi dans le lexique, à la fin, rangé par ordre alphabétique.

Comment le lire. Lis « Les bases » dans l’ordre, une partie à la fois, sans te presser. Ensuite, chaque leçon a deux encadrés pour t’aider : « Les mots de cette leçon » (les mots techniques du programme, expliqués) et « Le programme, ligne par ligne » (chaque ligne du programme dite en français).

Le plus important : essayer. On n’apprend pas à programmer en lisant seulement, comme on n’apprend pas le vélo dans un livre. Ouvre l’atelier, tape le programme de la leçon, appuie sur « Compiler et lancer », regarde ce qui se passe, puis change un nombre et relance. Se tromper fait partie du jeu : la console ne casse jamais.

1. Un ordinateur suit des instructions, une à une

Un ordinateur ne réfléchit pas : il obéit. Il fait exactement ce qu’on lui dit, dans l’ordre, très vite — des millions de fois par seconde — mais sans jamais deviner ce qu’on voulait dire.

Comme une recette de cuisine. « Casser deux œufs. Ajouter le sucre. Mélanger. » Chaque phrase est une instruction ; on les fait l’une après l’autre, de la première à la dernière. Un programme, c’est pareil : une liste d’instructions, écrites dans une langue que la machine comprend.

Il faut tout dire. Une personne comprend « mets un peu de sel ». Un ordinateur, non : il faut dire combien, où, et quand. C’est pour ça que le code paraît précis et un peu raide : il ne laisse rien au hasard.

2. La Game Boy : une petite console de 1989

La Game Boy est une console de jeux portable, sortie en 1989. On y glissait une cartouche — un petit boîtier de plastique qui contient un jeu. La Game Boy Color (1998) est la même console, avec des couleurs.

Son écran fait 160 pixels de large et 144 de haut. Un pixel est un tout petit carré de couleur : l’image entière est faite de 160 × 144 = 23 040 de ces carrés, comme une mosaïque.

Elle est très lente comparée à un téléphone d’aujourd’hui — des milliers de fois. C’est ce qui rend la programmation intéressante : chaque calcul compte, et on voit vraiment ce que fait la machine.

Tu n’as pas besoin d’une vraie Game Boy. L’atelier en contient une imitée dans le navigateur (on dit un émulateur) : elle fait exactement ce que ferait la vraie. La cartouche que tu fabriques marcherait aussi sur une vraie console.

3. Un programme, c’est un texte

Un programme s’écrit comme un texte, avec des lettres, des chiffres et quelques signes : ( ) { } ; = " ". Ici, on l’écrit dans le langage C++ (on dit « C plus plus »), un langage très utilisé pour les jeux vidéo.

Un langage de programmation a des règles strictes, comme l’orthographe, mais plus sévères : un signe oublié et la machine ne comprend plus. Pas de panique : l’atelier dit où est l’erreur et quoi corriger.

Le plus petit programme possible : il ne fait rien, mais il est juste.

int main() {
  while (true) {
    image();
  }
}

int main() veut dire « ici commence le programme » ; while (true) veut dire « recommence sans fin » ; image() veut dire « attends l’image suivante ». Les accolades { } entourent ce qui va ensemble. Tout cela est expliqué dans les parties suivantes.

4. Le compilateur : le traducteur

La console ne lit pas le C++. Elle ne comprend que des nombres : des suites d’octets (un octet est un nombre de 0 à 255). Il faut donc traduire le texte en nombres.

Le compilateur est ce traducteur. Quand tu appuies sur « Compiler et lancer », il lit ton programme du début à la fin, vérifie qu’il respecte les règles, puis le transforme en octets — environ 32 000 — qui forment une cartouche.

S’il trouve une erreur, il s’arrête et le dit : le numéro de la ligne, et ce qui ne va pas, en français. Par exemple : « ligne 5 : il manque un point-virgule ». C’est normal et utile : il vaut mieux une erreur dite tout de suite qu’un jeu qui fait n’importe quoi.

5. L’atelier : là où l’on écrit et où l’on joue

L’atelier est la page où tout se passe (index.html, ouverte par lancer.bat). À gauche : le programme, que tu écris. À droite : la console, qui joue la cartouche.

Le bouton « ▶ Compiler et lancer » (ou Ctrl + Entrée) traduit le programme et le lance aussitôt dans la console. En dessous, la page dit ce que la cartouche contient, ou l’erreur s’il y en a une.

Les touches du clavier font la manette : les flèches pour la croix, X pour le bouton A, Z pour B, Entrée pour START.

Les modes, en haut : 🎨 CRÉATION (écrire, dessiner, composer de la musique), 📚 APPRENDRE (les leçons, dans l’ordre), 🔎 MACHINE (ce que la console exécute vraiment), 🔗 LES SOURCES (tous les documents).

6. Lire une ligne de code

On lit de haut en bas, et chaque ligne de gauche à droite — comme un livre. La console exécute les instructions dans cet ordre.

Le point-virgule ; termine une instruction, comme le point termine une phrase. L’oublier est l’erreur la plus fréquente ; le compilateur la signale.

Les accolades { } regroupent des lignes qui vont ensemble : tout ce qui est entre { et } forme un bloc. Les lignes d’un bloc sont décalées vers la droite (on dit indentées) pour qu’on voie d’un coup d’œil ce qui est dedans. Le décalage n’est que pour l’œil : la console ne le regarde pas.

Les commentaires commencent par // : tout ce qui suit, jusqu’au bout de la ligne, est pour l’humain qui lit, et la console l’ignore. Ils expliquent ce que fait le code.

texte(1, 2, "BONJOUR");   // écrit BONJOUR en haut à gauche

Les majuscules comptent : score et Score sont deux noms différents. Et les noms n’ont ni espace ni accent : on écrit meilleurScore, pas « meilleur score ».

7. Écrire à l’écran : les coordonnées

Pour écrire, il faut dire OÙ. L’écran est découpé en une grille de 20 colonnes et 18 lignes ; chaque case fait 8 × 8 pixels et peut contenir une lettre.

La case (0, 0) est en haut à gauche. La première coordonnée est la colonne (vers la droite), la seconde la ligne (vers le bas). Attention : on compte à partir de zéro, pas de un. La colonne 19 est la dernière à droite, la ligne 17 la dernière en bas.

texte(5, 8, "SALUT");   // colonne 5, ligne 8 : à peu près au milieu

Des parenthèses après un nom, c’est un appel : texte(5, 8, "SALUT") demande à la console d’exécuter « texte » avec trois arguments — les valeurs entre parenthèses, séparées par des virgules. Le mot entre guillemets "…" est un texte tel quel.

Au pixel près, pour ce qui bouge : 160 pixels de large (0 à 159), 144 de haut (0 à 143). Les lutins (les personnages) se placent ainsi.

8. Retenir un nombre : la variable

Une variable est une boîte avec un nom, dans la mémoire de la console, qui retient un nombre. On peut lire ce nombre, et le changer.

uint8_t score = 0;   // une boîte « score », qui commence à 0

uint8_t veut dire « un nombre entier de 0 à 255 » (un octet). C’est le seul genre de nombre de cette console. Au-delà de 255, il repart à 0, comme le compteur kilométrique d’une vieille voiture qui repasse à zéro.

Le signe = veut dire « prend la valeur », pas « est égal ». score = score + 1; se lit : « score prend la valeur de score plus un » — il augmente de 1. On l’écrit aussi score++; ou score += 1;.

Une constante (const uint8_t VIES = 3;) est une variable qui ne change jamais : on lui donne un nom pour que le programme se lise mieux. On les écrit souvent en MAJUSCULES.

Un tableau (uint8_t cases[10];) est une rangée de boîtes sous un même nom : cases[0], cases[1] … cases[9]. Le nombre entre crochets dit laquelle ; on commence à 0.

9. La boucle du jeu : 60 images par seconde

Un jeu, c’est un dessin animé. La console montre 60 images par seconde ; entre deux images, le programme regarde la manette, déplace les personnages, et prépare l’image suivante.

while (true) {
  image();          // attendre l’image suivante
  // … ce qui se passe à chaque image
}

while (true) { … } répète ce qui est entre les accolades sans jamais s’arrêter : c’est la boucle du jeu. image() attend l’image suivante : sans elle, le programme irait trop vite et tout serait fini avant qu’on voie quoi que ce soit.

Ce qui est avant la boucle se fait une seule fois (préparer l’écran, mettre le score à zéro). Ce qui est dedans se fait 60 fois par seconde.

10. Décider : « si… sinon… »

if veut dire « si » : la console teste une condition ; si elle est vraie, elle fait ce qui est dans les accolades, sinon elle passe.

if (bouton(A)) {        // si le bouton A est enfoncé…
  texte(1, 1, "BRAVO");  // … écrire BRAVO
} else {                // sinon…
  texte(1, 1, "     ");  // … effacer
}

Comparer : == « est égal à » (deux signes =, pour ne pas confondre avec « prend la valeur »), != « est différent de », < « plus petit que », > « plus grand que », <= et >= « ou égal ».

Combiner : && veut dire « et » (les deux doivent être vrais), || veut dire « ou » (l’un des deux suffit), ! veut dire « pas ».

11. Répéter : les boucles qui comptent

for répète un nombre de fois connu. On lui donne un compteur, une condition pour continuer, et ce qu’on fait au compteur après chaque tour.

for (uint8_t i = 0; i < 5; i++) {   // i vaut 0, 1, 2, 3, 4
  texte(i, 3, "X");                  // un X dans les colonnes 0 à 4
}

while (condition) répète tant qu’une condition est vraie — on ne sait pas d’avance combien de fois. break; sort de la boucle tout de suite.

12. Ranger des gestes : les fonctions

Une fonction est un groupe d’instructions qui a un nom. On l’écrit une fois, puis on la lance autant de fois qu’on veut en écrivant son nom suivi de parenthèses.

void effacerLigne(uint8_t ligne) {       // une fonction à nous
  texte(0, ligne, "                    ");
}

effacerLigne(4);                          // on la lance pour la ligne 4

void dit que la fonction ne rend rien ; uint8_t nom(…) dit qu’elle rend un nombre, avec return. Ce qui est entre les parenthèses de sa définition (uint8_t ligne) sont ses paramètres : des boîtes qui reçoivent les valeurs données à l’appel.

La console a ses propres fonctions toutes prêtes : texte, poser, sprite, bouton, image… Ce sont elles qui touchent l’écran, la manette et le son.

13. « #include » : demander une fonction de la console

La cartouche est petite (32 768 octets pour tout le jeu). La console ne met donc dans ta cartouche que les fonctions que tu demandes.

#include <texte>    // « ce programme se sert de texte() »

Une ligne #include <nom> par fonction employée, en haut du programme. Sans elle, le compilateur refuse et dit laquelle ajouter. Une ligne de trop ne coûte rien.

#include "fichier.cpp" (avec des guillemets) est différent : il verse ton propre fichier à cet endroit, comme si son texte était écrit là. Ça permet de ranger un grand programme en plusieurs onglets.

14. Les dessins : pixels, tuiles et lutins

Une tuile est un petit dessin de 8 × 8 pixels. Le décor (le fond de l’écran) est une grille de tuiles, comme un carrelage. On l’écrit avec des signes, une rangée par ligne :

Tuile MUR = {
  "########",
  "#++#+++#",
  …
};

Chaque signe est un pixel : « . » le plus clair, « - » clair, « + » foncé, « # » le plus foncé. (On peut aussi écrire les chiffres 0, 1, 2, 3.) En couleur, ces quatre nuances deviennent les quatre couleurs d’une palette.

Un Perso est un dessin de 16 × 16 (ou 32 × 32) : quatre tuiles (ou seize) en carré.

Un lutin (en anglais « sprite ») est un dessin qui bouge librement, au pixel près, par-dessus le décor : le héros, les ennemis, une balle. poser() met une tuile dans le décor ; sprite() place un lutin.

Dessiner une fois, agrandir comme on veut : un nombre en plus à la fin — sprite16(0, 40, 40, HEROS, 3) — montre le dessin trois fois plus grand ; le compilateur le redessine, il n’y a toujours qu’un seul dessin.

15. Quand ça ne marche pas : les erreurs

Une erreur n’est pas un échec, c’est une information. Tous les programmeurs en font, tout le temps.

Lis le message : il donne la ligne et la raison. Va à cette ligne (le numéro est à gauche du programme) et regarde juste avant aussi : un point-virgule oublié à la ligne 4 est souvent signalé à la ligne 5.

Les erreurs les plus courantes : un ; oublié ; une accolade } en trop ou en moins ; un nom mal écrit (Texte au lieu de texte) ; un #include oublié ; un texte sans ses guillemets.

Avance par petits pas : change une seule chose, relance, regarde. Si ça casse, tu sais exactement ce qui a cassé. Et Ctrl + Z annule la dernière modification.

A. Ce que contient le dossier du projet

Le projet est un dossier (on dit aussi un répertoire) : un classeur dans ton ordinateur, qui contient des fichiers et d’autres dossiers. Chaque fichier a un nom et une extension — les lettres après le point — qui dit son genre :

- .cpp : un programme écrit en C++ (les jeux, les exemples) ;

- .js et .mjs : un programme écrit en JavaScript, le langage dans lequel l’atelier, le compilateur et l’émulateur sont écrits ;

- .html : une page web (l’atelier est une page web, ouverte dans le navigateur) ;

- .gb et .gbc : une cartouche (le jeu compilé, que la console joue) ;

- .md : un texte simple (les documents comme LISEZMOI.md) ; .pdf : un document à lire ou imprimer.

Voici le dossier, tel qu’il est en ce moment. La deuxième colonne dit à quoi sert chaque élément ; pour un fichier, c’est la première phrase de son propre commentaire, lue dans le fichier lui-même.

À retenir

Trois choses font tout le projet : l’atelier (index.html, la page où l’on écrit et où l’on joue), le compilateur (le dossier compilateur/, qui traduit le texte en cartouche) et l’émulateur (emulateur.js, la Game Boy imitée qui joue la cartouche). Tout le reste les aide : les leçons, les exemples, les outils, les vérifications, les documents.

B. Du texte à l’écran : suivre un vrai programme

Que se passe-t-il quand on appuie sur « Compiler et lancer » ? On va le voir en suivant un vrai programme, exemples/bonjour.cpp, à travers chaque étape. Tout ce qui est montré ici a été calculé par le vrai compilateur et le vrai émulateur au moment où ce document a été fabriqué.

L’idée générale, comme une chaîne de fabrication : le texte entre d’un côté ; chaque étape le transforme un peu ; une cartouche sort de l’autre côté, et la console la joue.

ton texte (.cpp)
   │  1. rassembler   — verser les fichiers #include "…" au bon endroit
   ▼
un seul texte
   │  2. analyser     — lire les mots et ranger le programme en arbre
   ▼

   │  3. compiler     — transformer l’arbre en instructions du processeur
   ▼

   │  4. fabriquer    — ajouter l’en-tête et les dessins : la cartouche
   ▼
une cartouche de 32 768 octets
   │  5. jouer        — l’émulateur exécute la cartouche, 60 images par seconde
   ▼
l’écran

Le programme de départ

Le voici, tel qu’il est dans le fichier :

// Une cartouche Game Boy, écrite en C++.
//
// Ce fichier est du vrai C++ : votre éditeur le colore, et il se lit comme
// n'importe quel autre. Il n'est pas compilé par g++ — il est traduit en code
// machine SM83 et gravé dans une cartouche de 32 Ko qui démarre sur une
// console d'origine.
//
//   node gb3.mjs exemples/bonjour.cpp

#include <texte>    // écrit un texte à l’écran
#include <bouton>   // lit un bouton de la manette

int main() {
  texte(6, 4, "BONJOUR");
  texte(3, 8, "APPUIE SUR A");

  uint8_t compte = 0;

  while (true) {
    image(); // attend l'image suivante : soixante fois par seconde

    if (bouton(A)) {
      texte(3, 8, "BRAVO       ");
      compte++;
    }

    if (bouton(B)) {
      texte(3, 8, "APPUIE SUR A");
    }
  }

  return 0;
}

Étape 1 — rassembler

Un programme peut tenir sur plusieurs fichiers. Une ligne #include "dessins.cpp" veut dire « verse ici le texte du fichier dessins.cpp ». La première étape fait ces versements, pour obtenir un seul texte. (C’est le fichier compilateur/inclusion.js.)

bonjour.cpp n’a qu’un fichier : le texte rassemblé fait 34 lignes, et les lignes #include <texte> (avec des chevrons) ne versent rien : elles demandent une fonction de la console, et le compilateur s’en souvient pour la suite.

Étape 2 — analyser : du texte à l’arbre

L’analyseur lit le texte mot à mot (compilateur/analyseur.js). Il reconnaît les mots du langage (int, while, if…), les noms (compte), les nombres, les textes entre guillemets, les signes — et il vérifie l’orthographe du C++ : une parenthèse oubliée, un point-virgule manquant, et il s’arrête en disant la ligne.

Il range le programme en arbre, comme un arbre généalogique : le programme contient la fonction main, qui contient des instructions, qui contiennent des appels, qui contiennent des valeurs. Voici le début de main, tel que l’analyseur l’a rangé (abrégé) :

Comment le lire : chaque { … } est un nœud de l’arbre ; genre dit ce que c’est (un appel, une boucle, une variable…), et les autres champs ses morceaux : nom le nom de la fonction appelée, arguments ce qu’on lui donne, valeur un nombre ou un texte, ligne la ligne du programme d’où vient le morceau — c’est grâce à elle qu’une erreur peut dire « ligne 14 ». Ici, la ligne 14, texte(6, 4, "BONJOUR");, est devenue un appel à « texte » avec trois arguments : les nombres 6 et 4, et le texte BONJOUR.

L’ordinateur travaille bien mieux sur cet arbre que sur le texte : tout y est déjà rangé et nommé.

Étape 3 — compiler : de l’arbre aux instructions

L’émetteur parcourt l’arbre (compilateur/emetteur.js) et, pour chaque nœud, écrit les instructions du processeur de la Game Boy (il s’appelle SM83). Ces instructions sont très simples : « mets ce nombre dans une case », « ajoute », « saute là-bas », « appelle cette routine ». Une seule ligne de C++ en donne souvent plusieurs.

Le résultat pour bonjour.cpp : 561 octets de programme, 1 variable. Voici le début de main, relu par le désassembleur (desassembleur.js) — l’adresse, les octets, l’instruction, et ce qu’elle veut dire :

Comment le lire, colonne par colonne : d’abord l’adresse ($0181…), écrite en hexadécimal — un nombre avec les chiffres 0-9 et A-F — : la place de l’instruction dans la cartouche. Puis les octets, la traduction exacte en nombres. Puis l’instruction, en assembleur. Enfin, après « ; », ce qu’elle veut dire en C++, quand on le sait.

Les quatre premières lignes sont texte(6, 4, "BONJOUR"); : ld hl, $9886 range dans la case « hl » l’adresse de la case de l’écran (colonne 6, ligne 4) ; ld de, Texte_2 range l’adresse du mot BONJOUR, gravé plus loin dans la cartouche ; ld b, 7 sa longueur, sept lettres ; call ecrire_… appelle la routine qui recopie les lettres à l’écran. Une ligne de C++, quatre instructions.

Les mots de l’assembleur : ld « charger » (ranger une valeur quelque part), call « appeler une routine » (puis revenir), jp / jr « sauter » ailleurs, inc « ajouter 1 », xor a « mettre a à zéro », bit « tester un bit ». Les noms comme AttendreImage ou LireManette sont des routines de la console : du code tout fait, ajouté parce que le programme a demandé image() et bouton(). tantque_4 est le début de la boucle while, et finsi_7 la fin d’un if : quand le bouton A n’est pas enfoncé, jp z, finsi_7 saute par-dessus ce qu’il y a dedans.

main.compte est la variable compte : le compilateur lui a donné une adresse dans la mémoire, et inc a entre deux ldh est le compte++; du programme.

H. Enregistrer et partager : git

git garde l’historique du projet, comme un album de photos : chaque commit est une photo du projet entier, avec une phrase qui dit ce qui a changé. On peut toujours revenir à une photo d’avant — rien n’est jamais perdu.

GitHub est un site qui garde une copie du projet sur internet. Pousser (push), c’est envoyer ses nouvelles photos là-bas : le projet est alors sauvegardé, et d’autres peuvent le voir.

Les trois commandes de tous les jours, dans une fenêtre de commande ouverte dans le dossier :

git status                          # ce qui a changé depuis la dernière photo
git add -A                          # tout préparer pour la photo
git commit -m "Ce que j’ai changé"  # prendre la photo, avec sa phrase
git push                            # l’envoyer sur GitHub

Ce qui n’est jamais envoyé est écrit dans le fichier .gitignore : par exemple le dossier cartouches/, qui contient des jeux du commerce (ils appartiennent à Nintendo, on n’a pas le droit de les partager).

L’historique de ce qui a changé, en phrases : documents/CHANGEMENTS.md, mis à jour à chaque étape.

Le lexique : chaque mot, expliqué simplement

Les 76 mots techniques qu’on rencontre dans ce document, par ordre alphabétique.

accolades { }Elles entourent un bloc : les lignes qui vont ensemble (le corps d’une fonction, d’une boucle, d’un « if »). Chaque « { » a son « } ».
affectation (=)« x = 5; » : la boîte x prend la valeur 5. Ce n’est pas une égalité : c’est un rangement.
analyseurLa première partie du compilateur : il lit le texte et en fait un arbre (compilateur/analyseur.js).
arbre (syntaxique)Ce que l’analyseur fabrique : le programme rangé comme un arbre généalogique — le programme contient des fonctions, qui contiennent des instructions, qui contiennent des valeurs.
argumentUne valeur donnée à une fonction quand on l’appelle, entre ses parenthèses : dans texte(5, 8, "SALUT"), 5, 8 et "SALUT" sont les arguments.
assembleurLa langue du processeur, écrite en mots courts (ld, call, jp…) : chaque mot est une instruction de la machine. Le compilateur traduit le C++ en assembleur, puis en octets.
blocUn groupe de lignes entre accolades { }, qui s’exécutent ensemble.
booléen (vrai / faux)Le résultat d’une condition : vrai (1) ou faux (0). « true » veut dire vrai, « false » faux.
boucleDes instructions qui se répètent : « while » (tant que…) ou « for » (pour un compteur qui va de… à…).
boucle du jeu« while (true) { image(); … } » : ce qui se répète 60 fois par seconde, sans fin, pendant tout le jeu.
bouton()Une fonction de la console qui dit si un bouton de la manette est enfoncé : 1 oui, 0 non. Les boutons : A, B, HAUT, BAS, GAUCHE, DROITE, START, SELECT.
breakSort tout de suite de la boucle (ou du « switch ») où l’on est.
C++Le langage dans lequel ces programmes sont écrits. Le compilateur de l’atelier en comprend une partie, adaptée à la Game Boy.
cartoucheLe boîtier qui contient un jeu ; ici, le fichier .gb (ou .gbc en couleur) que le compilateur fabrique : 32 768 octets.
chaîne de caractères (texte)Des lettres entre guillemets, "COMME CECI" : un texte pris tel quel. La police de la console n’a que des majuscules, sans accents.
commentaire (//)Tout ce qui suit « // » jusqu’au bout de la ligne : une phrase pour l’humain, que la console ignore.
commit (git)Une « photo » enregistrée du projet, avec un message qui dit ce qui a changé. On peut toujours revenir à une photo d’avant.
compilateurLe traducteur qui transforme le texte du programme en octets que la console comprend, et qui signale les erreurs.
conditionUne question dont la réponse est vrai ou faux : « score > 10 », « bouton(A) ». On la teste avec « if » ou « while ».
consoleLa machine qui joue : ici, la Game Boy (ou Game Boy Color), imitée dans le navigateur par l’émulateur.
constante (const)Une valeur qui a un nom et ne change jamais : « const uint8_t VIES = 3; ».
continuePasse directement au tour suivant de la boucle.
coordonnéesDeux nombres qui disent où : la colonne (vers la droite) puis la ligne (vers le bas), à partir de (0, 0) en haut à gauche.
couleur, paletteEn couleur (Game Boy Color), chaque dessin a quatre teintes ; une palette dit quelles couleurs. couleurFond() les règle pour le décor, couleurLutin() pour les lutins.
défilementLe décor qui glisse quand le héros avance : defiler(x, y) décale tout le fond.
dossierUn classeur dans l’ordinateur, qui contient des fichiers (et d’autres dossiers).
else (sinon)Ce que l’on fait quand la condition du « if » est fausse.
émetteurLa partie du compilateur qui transforme l’arbre en instructions du processeur (compilateur/emetteur.js).
émulateurUn programme qui imite une machine : ici, une Game Boy dans le navigateur.
fichierUn document enregistré dans l’ordinateur : un texte, une image, une cartouche… Son nom finit par une extension (.cpp, .js, .gb…) qui dit son genre.
fonctionUn groupe d’instructions qui a un nom, qu’on lance en écrivant son nom et des parenthèses. Celles de la console (texte, poser…) sont toutes prêtes ; on peut écrire les siennes.
forUne boucle qui compte : « for (uint8_t i = 0; i < 5; i++) » fait 5 tours, i valant 0, 1, 2, 3 puis 4.
gitUn programme qui garde l’historique du projet, photo après photo, et qui l’envoie sur internet (GitHub) pour le partager et le sauvegarder.
hasard()Une fonction de la console qui rend un nombre au hasard, de 0 à 255.
hexadécimalUne façon d’écrire les nombres avec 16 chiffres : 0 à 9 puis A à F. « $FF » veut dire 255 ; « $0150 » veut dire 336. Pratique pour les octets : un octet s’écrit toujours en deux chiffres.
HTMLLe langage des pages web : l’atelier (index.html) est une page HTML, que le navigateur affiche.
if (si)Teste une condition : si elle est vraie, on fait le bloc qui suit.
image()Attend l’image suivante. La console en montre 60 par seconde : c’est ce qui règle la vitesse d’un jeu.
#includeEn haut du programme : « #include <texte> » demande la fonction texte() à la console ; « #include "fichier.cpp" » verse un de tes fichiers à cet endroit.
incrémenter (++)« x++ » ou « x += 1 » : x augmente de 1. « x-- » : x diminue de 1.
indiceLe numéro d’une case dans un tableau, entre crochets : cases[3] est la quatrième case (on compte à partir de 0).
instructionUn ordre donné à la console, terminé par un point-virgule : « texte(1, 1, "OK"); ».
JavaScript (.js)Le langage dans lequel l’atelier, le compilateur et l’émulateur sont écrits. Le navigateur sait l’exécuter.
lutin (sprite)Un dessin qui bouge au pixel près, par-dessus le décor : le héros, un ennemi. sprite() en place un de 8 × 8, sprite16() un de 16 × 16. La console en a 40.
main« int main() { … } » : là où le programme commence. La console exécute d’abord la première ligne de main.
mémoire (RAM)Là où la console range ses variables pendant le jeu : 8 Ko de cases, effacées quand on l’éteint.
moduleUn fichier .js qui fait une seule chose et qui la prête aux autres (avec « export » et « import »).
navigateurLe programme qui affiche les pages web : Chrome, Edge, Firefox… L’atelier s’ouvre dedans.
Node.jsUn programme qui exécute du JavaScript en dehors du navigateur. Il fait tourner le petit serveur de l’atelier, les outils et les vérifications.
octetUn nombre de 0 à 255 : la plus petite boîte de la mémoire. Une cartouche en a 32 768.
opérateurs de calcul+ plus, - moins, * fois, / divisé par (sans virgule : 7 / 2 donne 3), % le reste de la division (7 % 2 donne 1).
opérateurs de comparaison== égal, != différent, < plus petit, > plus grand, <= plus petit ou égal, >= plus grand ou égal. Le résultat est vrai ou faux.
opérateurs logiques&& « et » (les deux doivent être vrais), || « ou » (un seul suffit), ! « pas ».
paramètreDans la définition d’une fonction, la boîte qui reçoit une valeur donnée à l’appel : dans « void f(uint8_t x) », x est un paramètre.
PersoUn dessin de 16 × 16 pixels (ou 32 × 32) : quatre tuiles en carré (ou seize). « Perso HEROS = { … }; ».
pixelUn tout petit carré de couleur ; l’écran en a 160 de large et 144 de haut.
point-virgule (;)Il termine une instruction, comme le point termine une phrase.
poser()Met une tuile dans le décor, sur une case de la grille de 20 × 18 (32 × 32 en tout, avec la partie cachée).
processeurLa puce qui exécute les instructions, une à une. Celle de la Game Boy s’appelle SM83 et fait environ 4 millions de pas par seconde.
programmeLa liste d’instructions qu’on écrit, et que le compilateur traduit en cartouche.
push (git)Envoyer ses commits sur internet (GitHub) : le projet y est alors sauvegardé et partagé.
registreUne toute petite case DANS le processeur (a, b, c, h, l…), où il fait ses calculs. Beaucoup plus rapide que la mémoire.
returnTermine la fonction et rend une valeur à celui qui l’a appelée.
ROMLa mémoire de la cartouche, qu’on lit sans pouvoir l’écrire : le programme, les dessins, les textes.
serveur (local)Un petit programme qui « sert » les pages de l’atelier au navigateur. lancer.bat le démarre ; il ne sort pas de ton ordinateur.
structUn modèle qui regroupe plusieurs boîtes sous un nom : « struct Ennemi { uint8_t x; uint8_t y; }; ».
switch / caseChoisir entre plusieurs cas selon la valeur d’une variable, au lieu d’une suite de « if ».
tableauUne rangée de boîtes sous un même nom : « uint8_t cases[10]; » donne cases[0] à cases[9].
taille (agrandir)Un nombre en dernier argument de sprite, sprite16, sprite32, poser… : le dessin, écrit une fois, montré autant de fois plus grand.
texte()Écrit des lettres à l’écran, sur la grille de 20 colonnes et 18 lignes : texte(colonne, ligne, "MOT").
TuileUn dessin de 8 × 8 pixels, écrit rangée par rangée avec des signes (. - + #). Le décor en est fait.
uint8_tLe genre de nombre de cette console : un entier de 0 à 255 (un octet). Au-delà, il repart à 0.
variableUne boîte avec un nom, dans la mémoire, qui retient un nombre qu’on peut lire et changer.
vérificationUn programme qui contrôle qu’un autre marche : il compile, fait tourner, appuie sur les boutons, et compare avec ce qui est attendu. ✓ veut dire « bon », ✗ « pas bon ».
voidDevant une fonction : elle ne rend rien, elle agit seulement.
while (tant que)Répète un bloc tant qu’une condition est vraie.
