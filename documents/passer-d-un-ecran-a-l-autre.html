Passer d’un écran à l’autre

Un titre, une partie, une fin — et le bouton qui mène de l’un à l’autre.

C’est le squelette de n’importe quel jeu : un écran d’accueil, la partie, l’écran de fin. Tout tient en trois pièces, et il n’y en a pas d’autres.

1Une variable dit où l’on est. Un octet, scene, qui vaut TITRE, JEU ou FIN. Le reste du programme ne fait que la lire.
2Un seul endroit change d’écran. allerA() éteint, efface, redessine, rallume. Si chaque bouton faisait son propre ménage, l’un finirait par oublier d’effacer, et deux écrans se mélangeraient.
3On ne redessine qu’au changement. Redessiner à chaque image coûterait 360 cases soixante fois par seconde, pour rien : l’écran ne bouge pas tant que la scène ne change pas.

1. Ce que ça donne

Les quatre images ci-dessous sont l’écran de la console émulée, photographié après chaque appui sur A. Le quatrième appui ramène au titre : la roue se referme.

TITRE— A →JEU— A →FIN— A →TITRE

Trois noms plutôt que trois nombres : scene == JEU se relit, scene == 1 demande de se souvenir. aAvant retient l’état du bouton à l’image précédente — on verra au chapitre 4 pourquoi il est indispensable.

effacer() — les 20 × 18 cases de l’écran
effacer();   // dans allerA(), avant de dessiner le nouvel écran

effacer() est une fonction de la console (demandée en haut par sa ligne #include) : sans argument, elle vide tout l’écran. Sans cet effacement, « A POUR JOUER » resterait sous « A POUR FINIR », les deux textes mélangés à l’écran.

un dessin par écran
void dessinerTitre() {
  texte(6, 5, "MON JEU");
  texte(4, 10, "A POUR JOUER");
}

void dessinerJeu() {
  texte(5, 4, "C EST PARTI");
  texte(4, 10, "A POUR FINIR");
}

void dessinerFin() {
  texte(7, 5, "FINI");
  texte(3, 10, "A POUR REVENIR");
}

Chacune ne sait que dessiner. Aucune ne décide de rien, aucune n’efface : c’est ce qui permet de les appeler depuis un seul endroit.

allerA — le seul endroit qui change d’écran
void allerA() {
  ecran(0);
  effacer();
  if (scene == TITRE) {
    dessinerTitre();
  }
  if (scene == JEU) {
    dessinerJeu();
  }
  if (scene == FIN) {
    dessinerFin();
  }
  ecran(1);
}

L’ordre compte. ecran(0) éteint l’affichage, on fait le ménage à l’abri, ecran(1) rallume. Repeindre 360 cases prend bien plus de temps qu’une image n’en contient : écran allumé, on verrait le ménage se faire.

main — la boucle, et le bouton
int main() {
  scene = TITRE;
  allerA();
  while (true) {
    image();
    a = bouton(A);
    if (a == 1) {
      if (aAvant == 0) {
        if (scene == TITRE) {
          scene = JEU;
        } else {
          if (scene == JEU) {
            scene = FIN;
          } else {
            scene = TITRE;
          }
        }
        allerA();
      }
    }
    aAvant = a;
  }

  return 0;
}

image() attend la fin de l’image en cours. En dehors du changement de scène, cette boucle ne fait rien d’autre que lire un bouton : c’est normal, l’écran est déjà peint.

3. Pourquoi ecran(0) avant d’effacer

Une Game Boy affiche soixante images par seconde. Entre deux images, elle laisse un court instant — le VBlank — pendant lequel la mémoire vidéo est libre. Poser 360 tuiles demande beaucoup plus que cet instant.

Le piège : si on efface écran allumé, le balayage passe pendant le ménage et affiche un mélange des deux écrans — un scintillement, ou une bande de l’ancien texte qui survit une fraction de seconde. Éteindre l’écran suspend le balayage : plus rien ne s’affiche pendant qu’on travaille, et tout apparaît d’un coup au rallumage.

4. Le détecteur de front

C’est le point qui casse le plus souvent, et il ne se voit pas dans le code :

a = bouton(A);
if (a == 1) {
  if (aAvant == 0) {   // ← le front : A vient tout juste d’être pressé
    ...
    allerA();
  }
}
aAvant = a;            // ← on retient l’état pour l’image suivante

bouton(A) ne dit pas « A vient d’être pressé » : il dit « A est enfoncé maintenant ». Un appui humain dure une dizaine d’images. Sans aAvant, la scène avancerait dix fois — on traverserait les trois écrans et on retomberait sur le titre avant d’avoir eu le temps de lire quoi que ce soit.

La comparaison a == 1 && aAvant == 0 n’est vraie qu’à une seule image : celle où le bouton passe de relâché à enfoncé. Un appui, une transition, quelle que soit sa durée.

5. Ce que la console a répondu

Ces trois lignes ne sont pas une promesse : la cartouche a été chargée dans l’émulateur, le bouton pressé, et scene relue dans la mémoire de la console.

  • au moment de l’appui, la scène avance d’un cran
    scene = 1
  • A maintenu trois secondes : plus rien ne bouge
    scene = 1
  • relâché puis repressé : la scène avance encore
    scene = 2

📖 Les mots de cette leçon — si tu débutes

  • accolades { } — Elles entourent un bloc : les lignes qui vont ensemble (le corps d’une fonction, d’une boucle, d’un « if »). Chaque « { » a son « } ».
  • affectation (=) — « x = 5; » : la boîte x prend la valeur 5. Ce n’est pas une égalité : c’est un rangement.
  • argument — Une valeur donnée à une fonction quand on l’appelle, entre ses parenthèses : dans texte(5, 8, "SALUT"), 5, 8 et "SALUT" sont les arguments.
  • bloc — Un groupe de lignes entre accolades { }, qui s’exécutent ensemble.
  • booléen (vrai / faux) — Le résultat d’une condition : vrai (1) ou faux (0). « true » veut dire vrai, « false » faux.
  • boucle — Des instructions qui se répètent : « while » (tant que…) ou « for » (pour un compteur qui va de… à…).
  • boucle du jeu — « while (true) { image(); … } » : ce qui se répète 60 fois par seconde, sans fin, pendant tout le jeu.
  • bouton() — Une fonction de la console qui dit si un bouton de la manette est enfoncé : 1 oui, 0 non. Les boutons : A, B, HAUT, BAS, GAUCHE, DROITE, START, SELECT.
  • chaîne de caractères (texte) — Des lettres entre guillemets, "COMME CECI" : un texte pris tel quel. La police de la console n’a que des majuscules, sans accents.
  • commentaire (//) — Tout ce qui suit « // » jusqu’au bout de la ligne : une phrase pour l’humain, que la console ignore.
  • condition — Une question dont la réponse est vrai ou faux : « score > 10 », « bouton(A) ». On la teste avec « if » ou « while ».
  • coordonnées — Deux nombres qui disent où : la colonne (vers la droite) puis la ligne (vers le bas), à partir de (0, 0) en haut à gauche.
  • else (sinon) — Ce que l’on fait quand la condition du « if » est fausse.
  • fonction — Un groupe d’instructions qui a un nom, qu’on lance en écrivant son nom et des parenthèses. Celles de la console (texte, poser…) sont toutes prêtes ; on peut écrire les siennes.
  • if (si) — Teste une condition : si elle est vraie, on fait le bloc qui suit.
  • image() — Attend l’image suivante. La console en montre 60 par seconde : c’est ce qui règle la vitesse d’un jeu.
  • #include — En haut du programme : « #include <texte> » demande la fonction texte() à la console ; « #include "fichier.cpp" » verse un de tes fichiers à cet endroit.
  • incrémenter (++) — « x++ » ou « x += 1 » : x augmente de 1. « x-- » : x diminue de 1.
  • instruction — Un ordre donné à la console, terminé par un point-virgule : « texte(1, 1, "OK"); ».
  • main — « int main() { … } » : là où le programme commence. La console exécute d’abord la première ligne de main.
  • octet — Un nombre de 0 à 255 : la plus petite boîte de la mémoire. Une cartouche en a 32 768.
  • opérateurs de comparaison — == égal, != différent, < plus petit, > plus grand, <= plus petit ou égal, >= plus grand ou égal. Le résultat est vrai ou faux.
  • point-virgule (;) — Il termine une instruction, comme le point termine une phrase.
  • return — Termine la fonction et rend une valeur à celui qui l’a appelée.
  • texte() — Écrit des lettres à l’écran, sur la grille de 20 colonnes et 18 lignes : texte(colonne, ligne, "MOT").
  • uint8_t — Le genre de nombre de cette console : un entier de 0 à 255 (un octet). Au-delà, il repart à 0.
  • variable — Une boîte avec un nom, dans la mémoire, qui retient un nombre qu’on peut lire et changer.
  • void — Devant une fonction : elle ne rend rien, elle agit seulement.
  • while (tant que) — Répète un bloc tant qu’une condition est vraie.

poser()Met une tuile dans le décor, sur une case de la grille de 20 × 18 (32 × 32 en tout, avec la partie cachée).
programmeLa liste d’instructions qu’on écrit, et que le compilateur traduit en cartouche.
returnTermine la fonction et rend une valeur à celui qui l’a appelée.
structUn modèle qui regroupe plusieurs boîtes sous un nom : « struct Ennemi { uint8_t x; uint8_t y; }; ».
switch / caseChoisir entre plusieurs cas selon la valeur d’une variable, au lieu d’une suite de « if ».
tableauUne rangée de boîtes sous un même nom : « uint8_t cases[10]; » donne cases[0] à cases[9].
taille (agrandir)Un nombre en dernier argument de sprite, sprite16, sprite32, poser… : le dessin, écrit une fois, montré autant de fois plus grand.
texte()Écrit des lettres à l’écran, sur la grille de 20 colonnes et 18 lignes : texte(colonne, ligne, "MOT").
TuileUn dessin de 8 × 8 pixels, écrit rangée par rangée avec des signes (. - + #). Le décor en est fait.
uint8_tLe genre de nombre de cette console : un entier de 0 à 255 (un octet). Au-delà, il repart à 0.
variableUne boîte avec un nom, dans la mémoire, qui retient un nombre qu’on peut lire et changer.
voidDevant une fonction : elle ne rend rien, elle agit seulement.
while (tant que)Répète un bloc tant qu’une condition est vraie.
