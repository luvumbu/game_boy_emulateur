52. Nommer un geste qu’on refait

Une fonction avec un argument, et trois appels.

1. Ce qu’il faut comprendre

Les fonctions prennent des arguments, et c’est là tout l’intérêt. Sans argument, il faudrait trois fonctions, ou une variable globale à poser avant chaque appel.

void dit qu’elle ne rend rien. Le compilateur le vérifie : une fonction qui annonce rendre un uint8_t sans jamais faire return est refusée, avec sa ligne.

2. Le programme, morceau par morceau

Le programme entier de la leçon, découpé comme l’œil le lit. Il fait 1370 octets de cartouche.

1. un dessin — BRIQUE

Tuile BRIQUE = {
  "########", "#..#..#.", "########", "..#..#..",
  "########", "#..#..#.", "########", "..#..#..",
};

2. une fonction — rangee()

void rangee(uint8_t ligne) {
  for (uint8_t x = 0; x < 20; x++) poser(x, ligne, BRIQUE);
}

3. le point d’entrée : c’est ici que la console arrive

int main() {
  rangee(4);
  rangee(9);
  rangee(14);

  while (true) {
    image();
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

4. Ce qu’on doit voir

Trois rangées de briques, écrites par un seul bout de code.

5. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • la première rangée est posée
  • la deuxième aussi
  • et la troisième
  • rien entre les rangées

6. La même chose, à la souris

Cette leçon porte son atelier : le geste réécrit le programme ci-dessus, et la cartouche se refait dans la seconde. C’est le même texte, écrit autrement.
