27.1. La fonction ecran() — éteindre et rallumer l’écran

#include <ecran> : ecran(0) éteint l’écran, ecran(1) le rallume — le temps de dessiner beaucoup d’un coup.

1. Ce qu’il faut comprendre

Ce qu’elle fait : ecran(0) éteint l’écran, ecran(1) le rallume. Écran éteint, on peut écrire dans toutes les cases sans attendre : c’est le moment d’un gros dessin, comme tout un niveau.

La ligne à écrire : #include <ecran>.

Son argument : 0 ou 1, écrit en clair.

Ce qu’elle coûte : environ 90 octets avec la mise en place de l’écran ; un appel seul, quatre octets.

Essaie : enlève ecran(1) : l’écran reste blanc, le programme continue pourtant.

1. ce que le programme raconte de lui-même

// ---- #include <ecran> : éteindre et rallumer l'écran ----
// Écran éteint, on remplit trois lignes d'un coup, puis on le rallume.

#include <ecran>      // ecran() : éteindre (0), rallumer (1)
#include <poserS>
#include <ALPHABET>

2. le point d’entrée : c’est ici que la console arrive

int main() {
  ecran(0);                          // éteint : on écrit sans attendre
  for (uint8_t i = 0; i < 60; i++) {
    poserS(i, 4, ALPHABET[0]);       // 60 A : trois lignes pleines
  }
  ecran(1);                          // rallumé : tout apparaît d'un coup

  while (true) {
    image();
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

4. Ce qu’on doit voir

Trois lignes pleines de A, apparues d’un seul coup.

5. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • l’écran est rallumé
  • les trois lignes sont pleines
