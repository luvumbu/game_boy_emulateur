70. Des ennemis qui vivent et qui meurent

Les méthodes, dans un vrai tour de boucle.

1. Ce qu’il faut comprendre

hasard() lit le compteur libre du matériel : un nombre imprévisible, sans table ni graine. semer(n) permet de choisir son point de départ quand on veut au contraire une suite reproductible.

cacher(n) ôte le lutin de l’écran. Sans lui, un ennemi mort resterait affiché, immobile — ce qui se remarque tout de suite, heureusement.

2. Le programme, morceau par morceau

Le programme entier de la leçon, découpé comme l’œil le lit. Il fait 1782 octets de cartouche.

1. un dessin — ENNEMI

Tuile ENNEMI = {
  ".######.", "#-#--#-#", "########", "#.####.#",
  "########", ".#.##.#.", "#..##..#", ".#....#.",
};

2. un enregistrement — Monstre

struct Monstre {
  uint8_t x, y, vie;

  uint8_t vivant() { return vie > 0; }
  void avancer()   { if (vivant()) x++; }
  void tuer()      { vie = 0; }
};

3. un tableau — troupe

Monstre troupe[3];

4. le point d’entrée : c’est ici que la console arrive

int main() {
  for (uint8_t i = 0; i < 3; i++) {
    troupe[i].x = 10 + i * 30;
    troupe[i].y = 40 + i * 24;
    troupe[i].vie = 1;
  }

  uint8_t avant = 0;

  while (true) {
    uint8_t appui = bouton(A);
    if (appui && !avant) troupe[hasard() % 3].tuer();
    avant = appui;

    for (uint8_t i = 0; i < 3; i++) {
      troupe[i].avancer();
      if (troupe[i].vivant()) sprite(i, troupe[i].x, troupe[i].y, ENNEMI);
      else cacher(i);
    }
    image();
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

Chaque bouton que le programme lit a été enfoncé douze images, puis relâché. Voici l’écran juste après.
