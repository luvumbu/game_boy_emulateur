5. Une constante plutôt qu’un nombre

Nommer ne coûte rien du tout — et c’est la seule chose ici qui soit gratuite.

1. Ce qu’il faut comprendre

Un nombre écrit trois fois, ce sont trois occasions de le changer à deux endroits. Une const lui donne un nom.

Et elle ne prend aucun octet de mémoire. Elle est connue à la compilation : le compilateur remplace COLONNE par 5 dans le code machine, et il n’en reste rien dans la cartouche.

Comparer les deux compilations le montre — le nombre de variables annoncé ne bouge pas.

2. Le programme, morceau par morceau

Le programme entier de la leçon, découpé comme l’œil le lit. Il fait 1304 octets de cartouche.

1. une constante — COLONNE

const uint8_t COLONNE = 5;

2. une constante — LIGNE

const uint8_t LIGNE = 6;

3. le point d’entrée : c’est ici que la console arrive

int main() {
  texte(COLONNE, LIGNE, "BONJOUR");
  texte(COLONNE, LIGNE + 2, "ENCORE");

  while (true) {
    image();
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

4. Ce qu’on doit voir

« BONJOUR » puis « ENCORE », deux lignes plus bas.

5. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • « BONJOUR » est à la colonne nommée
  • « ENCORE » est deux lignes plus bas
