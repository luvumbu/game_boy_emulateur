10. Lire un bouton

Réagir à la manette.

1. Ce qu’il faut comprendre

bouton(A) rend 1 tant que le bouton est enfoncé. Les huit noms existent : A B HAUT BAS GAUCHE DROITE START SELECT.

Ici on lit le niveau : tant que A est tenu, le texte change. C’est ce qu’on veut pour courir ou viser — mais pas pour un menu : c’est la leçon « le front » qui règle ce cas.

&&, || et ! s’écrivent comme en C++, et s’arrêtent dès que la réponse est connue : dans i < n && t[i] == 0, la case n’est pas lue si l’index est hors du tableau.

2. Le programme, morceau par morceau

Le programme entier de la leçon, découpé comme l’œil le lit. Il fait 1410 octets de cartouche.

1. le point d’entrée : c’est ici que la console arrive

int main() {
  texte(3, 5, "APPUIE SUR A");

  while (true) {
    image();

    if (bouton(A) && !bouton(B)) {
      texte(3, 5, "BRAVO       ");
    }

    if (bouton(B)) {
      texte(3, 5, "APPUIE SUR A");
    }
  }

  return 0;
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

4. Ce que les touches changent

Chaque bouton que le programme lit a été enfoncé douze images, puis relâché. Voici l’écran juste après.

5. Ce qu’on doit voir

« BRAVO » pendant qu’on tient A ; B remet le texte de départ.

6. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • A écrit « BRAVO »
  • B le remet comme avant
