0.68.4. La fonction lire() — lire une case

#include <lire> : lire(colonne, ligne) rend la tuile posée dans cette case — de quoi savoir si elle est libre.

1. Ce qu’il faut comprendre

Ce qu’elle fait : lire(colonne, ligne) rend le numéro de la tuile affichée dans cette case. Une case vide rend 0. C’est ainsi qu’un jeu sait s’il y a un mur devant le joueur, sans tenir un tableau à côté.

La ligne à écrire : #include <lire>.

Ses arguments : la colonne et la ligne.

Ce qu’elle coûte : environ 90 octets la première fois.

Essaie : lis la case (4, 3), qui est vide : t vaut 0, et le programme écrit NON.

On retrouve lire dans 43 leçons

1. ce que le programme raconte de lui-même

// ---- #include <lire> : lire une case ----

#include <poser>
#include <ALPHABET>
#include <texte>
#include <lire>       // lire() : la tuile d'une case

2. une variable — t

uint8_t t = 0;

3. le point d’entrée : c’est ici que la console arrive

int main() {
  poser(3, 3, ALPHABET[0]);    // un A en (3, 3)
  t = lire(3, 3);              // t reçoit le numéro de la tuile : 1, celui du A

  if (t == ALPHABET[0]) {      // est-ce un A ?
    texte(3, 5, "OUI");
  } else {
    texte(3, 5, "NON");
  }

  while (true) {
    image();
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

4. Ce qu’on doit voir

Un A, et OUI en dessous : la case lue porte bien un A.

5. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • t vaut 1, le numéro du A (1)
  • le programme a écrit OUI
