63. Une table gravée

Ce qui ne change jamais n’a rien à faire en mémoire.

1. Ce qu’il faut comprendre

const uint8_t T[] est gravé dans la cartouche, comme une tuile. Le compilateur l’annonce : ces octets sortent du décompte de la mémoire de travail.

Ôter le const la met en mémoire — et la rend modifiable, et la rend vide au démarrage. Les deux formes ont leur usage ; la différence se voit dans le compte rendu de compilation, et nulle part ailleurs.

Les fonctions de cette leçon — et le tuto de chacune

  • #include <poser> → 0.1.3. La fonction poser() — poser une tuile

2. Le programme, morceau par morceau

Le programme entier de la leçon, découpé comme l’œil le lit. Il fait 242 octets de cartouche.

Ce que le compilateur y a gravé, nommé — chaque morceau, sa taille, qui l’a demandé — et ce qu’il a laissé, parce que rien ne l’appelle :

Gravé dans la cartouche :

  main()           58 o  ← démarrage  — ta fonction

1. ce que le programme raconte de lui-même

// CE PROGRAMME : pose 6 tuiles à des places écrites dans deux tableaux.
//
// const devant un tableau : il est GRAVÉ dans la cartouche et ne change jamais.
// Les deux tableaux vont ensemble : la place numéro i est (COLONNES[i], LIGNES[i]).

#include <poser>   // pose une tuile sur une case du fond

2. une table gravée dans la cartouche — COLONNES

const uint8_t COLONNES[] = { 2, 5, 8, 11, 14, 17 };   // les colonnes des 6 places

3. une table gravée dans la cartouche — LIGNES

const uint8_t LIGNES[]   = { 3, 6, 9, 6, 3, 6 };      // les lignes des 6 places

4. le point d’entrée : c’est ici que la console arrive

int main() {                                    // Le jeu commence ici.
  for (uint8_t i = 0; i < sizeof(COLONNES); i++)  // sizeof = le nombre de cases : 6.
    poser(COLONNES[i], LIGNES[i], 1);           //   Une tuile 1 (le A) à la place i.
                                                //   i = 0 → (2, 3) ; i = 2 → (8, 9) ...

  while (true) {                                // Répète pour toujours :
    image();                                    //   attend l'image suivante.
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

4. Ce qu’on doit voir

Six tuiles posées en zigzag, aux positions de la table.

5. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • la première est posée
  • la quatrième aussi
  • la dernière ferme le zigzag
  • et rien n’est posé entre deux
