126. Passer d’un écran à l’autre

Un titre, une partie, une fin.

1. Ce qu’il faut comprendre

Le squelette de n’importe quel jeu. Deux règles, et il n’y en a pas d’autres.

Une variable dit où l’on est. Un enum lui donne ses valeurs possibles, et leur donne des noms : TITRE, JEU, FIN. Le nom de l’enum devient un type d’un octet, et Scene scene se lit mieux que uint8_t scene.

Un seul endroit change d’écran. allerA() éteint, efface, redessine, rallume — toujours dans cet ordre. Si chaque bouton faisait son propre ménage, l’un finirait par oublier d’effacer, et deux écrans se mélangeraient.

Le switch aiguille sur la scène. Il fonctionne comme en C++, break compris : sans lui, l’exécution tombe dans le cas suivant. C’est un piège célèbre, mais c’est le sens du langage, et le trahir en douce serait pire.

On éteint l’écran pour effacer parce que repeindre toute la carte demande bien plus de temps qu’une image n’en contient. effacer() sans argument vide les 32 × 32 de la carte d’un coup — cette leçon écrivait autrefois ses deux boucles à la main, et n’effaçait alors que les 20 × 18 visibles : le décor qui défilait ramenait l’écran d’avant.

Les fonctions de cette leçon — et le tuto de chacune

  • #include <ecran> → 27.1. La fonction ecran() — éteindre et rallumer l’écran
  • #include <effacer> → 0.16.3. La fonction effacer() — effacer des cases
  • #include <texte> → 0.0.2. La fonction texte() — écrire un mot
  • #include <bouton> → 0.65.5. La fonction bouton() — lire la manette

1. ce que le programme raconte de lui-même

#include <ecran>     // éteint ou rallume l’écran
#include <effacer>   // efface des cases, ou tout le fond
#include <texte>     // écrit un texte à l’écran
#include <bouton>    // lit un bouton de la manette

2. des constantes nommées — Scene

enum Scene { TITRE, JEU, FIN };

3. une variable — scene

Scene scene = TITRE;

4. une fonction — allerA()

void allerA(Scene ou) {
  scene = ou;

  ecran(0);
  effacer();

  switch (scene) {
    case TITRE:
      texte(6, 5, "MON JEU");
      texte(4, 10, "A POUR JOUER");
      break;

    case JEU:
      texte(5, 4, "C EST PARTI");
      texte(4, 10, "A POUR FINIR");
      break;

    case FIN:
      texte(7, 5, "FINI");
      texte(3, 10, "A POUR REVENIR");
      break;
  }

  ecran(1);
}

5. le point d’entrée : c’est ici que la console arrive

int main() {
  uint8_t aAvant = 0;

  allerA(TITRE);

  while (true) {
    image();

    uint8_t a = bouton(A);

    if (a && !aAvant) {
      if (scene == TITRE) allerA(JEU);
      else if (scene == JEU) allerA(FIN);
      else allerA(TITRE);
    }

    aAvant = a;
  }

  return 0;
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

« MON JEU », puis A change d’écran à chaque appui.

6. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • on démarre sur le titre
  • A mène à la partie
  • puis à la fin
  • et on revient au titre
  • l’ancien écran est effacé
