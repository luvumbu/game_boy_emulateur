16. Deux touches, deux effets

Un `enum` donne des noms à des nombres, et `switch` les range côte à côte.

1. Ce qu’il faut comprendre

TITRE vaut 0, JEU vaut 1, FIN vaut 2 — mais on ne l’écrit jamais, et c’est tout l’intérêt : ajouter une scène au milieu ne renumérote rien à la main.

Scene devient un type d’un octet. Scene ou = TITRE; se relit mieux que uint8_t ou = 0;, et dit ce que la variable a le droit de contenir.

C’est la forme que prend presque tout jeu : quelques scènes, et un switch qui dit laquelle est en cours.

2. Le programme, morceau par morceau

Le programme entier de la leçon, découpé comme l’œil le lit. Il fait 1441 octets de cartouche.

1. des constantes nommées — Scene

enum Scene { TITRE, JEU, FIN };

2. le point d’entrée : c’est ici que la console arrive

int main() {
  Scene ou = TITRE;

  while (true) {
    switch (ou) {
      case TITRE:
        texte(4, 8, "APPUIE START");
        if (bouton(START)) { texte(4, 8, "            "); ou = JEU; }
        break;
      case JEU:
        texte(4, 8, "ON JOUE     ");
        if (bouton(SELECT)) ou = FIN;
        break;
      case FIN:
        texte(4, 8, "C EST FINI  ");
        break;
    }
    image();
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

4. Ce que les touches changent

Chaque bouton que le programme lit a été enfoncé douze images, puis relâché. Voici l’écran juste après.

5. Ce qu’on doit voir

START passe au jeu, SELECT y met fin.

6. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.
