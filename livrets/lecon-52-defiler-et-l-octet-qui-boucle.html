52. defiler(), et l’octet qui boucle

La carte fait 256 pixels — la même taille qu’un octet.

1. Ce qu’il faut comprendre

defiler(x, y) fait glisser tout le fond. La carte fait 256 pixels de côté et revient toute seule à zéro.

glisse est un octet : il boucle exactement au bon moment, sans qu’on ait rien à écrire. C’est une coïncidence heureuse du matériel, et l’un des rares endroits où le débordement d’un octet est ce qu’on veut.

Les fonctions de cette leçon — et le tuto de chacune

  • #include <Tuile> → 0.107.2. Tuile — dessiner une case
  • #include <poser> → 0.1.3. La fonction poser() — poser une tuile
  • #include <bouton> → 0.65.5. La fonction bouton() — lire la manette
  • #include <defiler> → 0.90.3. La fonction defiler() — faire glisser le fond

2. Le programme, morceau par morceau

Le programme entier de la leçon, découpé comme l’œil le lit. Il fait 301 octets de cartouche.

1. ce que le programme raconte de lui-même

// CE PROGRAMME : remplit l'écran d'un motif en diagonale ; GAUCHE / DROITE
// font glisser tout le décor, pixel par pixel.
//
// defiler(x, y) déplace la « fenêtre » par laquelle on voit le fond, en pixels.
// Rien n'est redessiné : c'est une seule écriture, très rapide.
// La carte du fond fait 256 pixels de large : « glisse », un uint8_t (0 à 255),
// repasse de 255 à 0 juste au moment où la carte recommence. Elle boucle.

#include <Tuile>     // un dessin de 8 × 8 pixels
#include <poser>     // pose une tuile sur une case du fond
#include <bouton>    // lit un bouton de la manette
#include <defiler>   // fait glisser tout le fond

2. un dessin — MOTIF

Tuile MOTIF = {                         // Une diagonale de # sur un fond de -.
  "#-------", "-#------", "--#-----", "---#----",
  "----#---", "-----#--", "------#-", "-------#",
};

3. le point d’entrée : c’est ici que la console arrive

int main() {                            // Le jeu commence ici.
  for (uint8_t y = 0; y < 18; y++)      // Chaque ligne y (0 à 17)...
    for (uint8_t x = 0; x < 20; x++)    //   ... chaque colonne x (0 à 19) :
      poser(x, y, MOTIF);               //     le motif. (Sans accolades, chaque for
                                        //     ne répète que l'instruction qui le suit.)

  uint8_t glisse = 0;                   // De combien de pixels le décor a glissé.

  while (true) {                        // Répète pour toujours :
    if (bouton(DROITE)) glisse++;       //   DROITE : un pixel de plus
    if (bouton(GAUCHE)) glisse--;       //   GAUCHE : un pixel de moins (0 - 1 donne 255)
    defiler(glisse, 0);                 //   On déplace la fenêtre.
    image();                            //   Attend l'image suivante.
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

4. Ce que les touches changent

Chaque bouton que le programme lit a été enfoncé douze images, puis relâché. Voici l’écran juste après.

5. Ce qu’on doit voir

DROITE et GAUCHE font glisser le motif sans fin.

6. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • DROITE fait défiler (0 → 30)
  • le défilement reste dans un octet
  • il repasse par zéro sans rien casser (29)
  • le motif couvre tout l’écran
