31. Déplacer un lutin

Une position, quatre boutons — et surtout pas de front.

1. Ce qu’il faut comprendre

Ici l’on veut que ça bouge tant que le doigt reste appuyé. Pas de front, donc : le front sert à ce qui doit arriver une fois, pas à ce qui doit durer.

Savoir lequel des deux on veut est la moitié du travail sur cette machine.

2. Le programme, morceau par morceau

Le programme entier de la leçon, découpé comme l’œil le lit. Il fait 1408 octets de cartouche.

1. un dessin — HEROS

Tuile HEROS = {
  "..####..", ".#-##-#.", "########", "#.####.#",
  "########", "..#..#..", ".#....#.", "##....##",
};

2. le point d’entrée : c’est ici que la console arrive

int main() {
  uint8_t x = 76;
  uint8_t y = 68;

  while (true) {
    if (bouton(GAUCHE)) x--;
    if (bouton(DROITE)) x++;
    if (bouton(HAUT))   y--;
    if (bouton(BAS))    y++;

    sprite(0, x, y, HEROS);
    image();
  }
}

3. Ce qui se passe, étape par étape

La cartouche a été compilée et exécutée pour de bon ; voici son écran aux instants qui comptent. Une image identique à la précédente n’est pas montrée — un programme qui ne bouge pas n’a qu’une seule image, et c’est la vérité sur ce programme.

4. Ce que les touches changent

Chaque bouton que le programme lit a été enfoncé douze images, puis relâché. Voici l’écran juste après.

5. Ce qu’on doit voir

La croix déplace le personnage, pixel par pixel.

6. Ce que la console répond

Ces contrôles ne sont pas décoratifs : ce sont ceux que verifier-tuto.mjs exige de cette leçon. Ils viennent d’être joués, et voici ce qu’ils ont mesuré.

  • DROITE le fait avancer (76 → 96)
  • il avance d’un pixel par image, pas d’une case
  • BAS le fait descendre (88)
  • tenir la touche continue de le déplacer
